# Echelon — заметки для агентов

Любительский некоммерческий ремейк аркадных авиасимуляторов «Шторм» / *Echelon*
(Steam 311080) и «Шторм: Солдаты Неба» / *Echelon: Wind Warriors* (Steam 311100).
Оригинал: движок MADia «Storm», DirectX 7, исходников нет. Форматы, оси,
экспорт и открытые вопросы — в `docs/specs/`. Здесь только то, без чего
нельзя собрать ремейк или легко сломать уже работающее.

## Цели и ограничения

- Сохранить сюжет, озвучку и аркадную авиамодель оригинала; графика новая
  (лучше освещение, простые шейдерные эффекты — ничего сложного).
- Позже: физика обломков, правка баланса. **Отложено пользователем:** геймпад,
  авто/быстрые сохранения — не делать без явной просьбы.
- `legacy/` (установленные игры) и `assets/legacy/` (всё извлечённое из них) —
  только референс, **никогда не коммитить** (уже в `.gitignore`). В репозитории
  живут только наши собственные ассеты (`assets/data`, `assets/shaders`,
  `assets/textures`) и инструменты извлечения.
- Общение с пользователем — на русском. Код, комментарии и лог — на английском.
- При затруднении или неоднозначности **спрашивать**, а не выбирать молча.
  Вопрос задавать сразу, как только развилка видна, не откладывая до конца
  задачи. Если по ходу вскрывается вторая трактовка уже принятого решения —
  остановиться и уточнить, даже если часть работы уже сделана.

## Стек и сборка

- C++20, CMake ≥ 4.0, Visual Studio 2022 (x64). Флаги `/W4 /WX` (см. `cxxflags.cmake`,
  INTERFACE-таргет `ECH_CXX_FLAGS`) — предупреждения ломают сборку.
- OpenGL 4.1 core (кросс-платформенно, Direct3D отклонён), загрузчик **GLEW**
  (статический, `ext/glew`, бинарники предоставляет пользователь), GLFW, GLM,
  stb — всё из `ext/`. Шейдеры `#version 410 core`.
- Boost 1.90 модульный checkout (`C:\Utils\boost\boost-1.90.0`, переопределяется
  `ECH_BOOST_SOURCE_DIR` / `BOOST_ROOT`), подключается через `add_subdirectory`
  с `BOOST_INCLUDE_LIBRARIES json test`. Данные — **JSON через Boost.JSON**
  (YAML отклонён). Тесты — Boost.Test, один бинарник `master-test-suite`.
- Команды:
  - конфигурация: `cmake\gen-msvc17-x64.bat` → `build-x64-msvc17/`
  - сборка: `cmake --build build-x64-msvc17 --config Release --parallel`
  - тесты: `.\build-x64-msvc17\tests\Release\master-test-suite.exe`
  - запуск: `.\build-x64-msvc17\src\app\Release\echelon.exe` (рабочая директория — корень репо,
    иначе `--assets <dir>`).
- Python в системе есть, но **без numpy** — вспомогательные скрипты только на stdlib.
- В PowerShell inline `python -c "..."` со скобками/кавычками ломается — временные
  скрипты писать в `tools/temp/` (в `.gitignore`) и запускать оттуда.
  **Не использовать `$env:TEMP` и прочие каталоги вне репозитория** — они засоряют
  систему и остаются после сессии. Для кириллицы: `$env:PYTHONIOENCODING="utf-8"`.

## Структура

- `src/core` — `echelon_core` (без зависимостей от GL): лог (`ech::log`),
  `math/curve` (кусочно-линейная кривая), `math/frame` (конвертация систем
  координат оригинала), `math/color` (sRGB ↔ линейный, пропускание тумана),
  `data/craft_spec` (JSON → `CraftSpec`),
  `sim/flight` (аркадный интегратор), `sim/fixed_step`,
  `terrain/heightfield` (`.eterr` → высоты, `heightAt` по правилу диагоналей
  оригинала, слои текстур по маске ячеек).
- `src/app` — исполняемый `echelon`: `platform/` (окно GLFW, ввод), `render/`
  (шейдер, меш, текстура, `Model` — загрузчик экспортированных моделей,
  `FlyCamera`, `Frame` — общие uniform'ы кадра, `TerrainRenderer`),
  `app.cpp` — песочница ассетов: ландшафт + все экспортированные самолёты в
  ряд на аэродроме Continent. **Полёт в песочнице пока отключён по просьбе
  пользователя** (код `sim/flight` и тесты остаются).
- `tests/` — Boost.Test; `tools/legacy_export.py` — экспортёр моделей;
  `tools/terrain_export.py` — экспортёр ландшафта (переиспользует `Container`
  и `decode_dxt` из `legacy_export.py`);
  `tools/pe_survey.py` — обзор DLL оригинала (экспорты, импорты, строки `.cpp`),
  без дизассемблирования. Разовые пробники по-прежнему в `tools/temp/`.
- `docs/specs/` — спецификации форматов и открытые вопросы. Новые находки о
  файлах писать туда, не в этот файл.
- `assets/data/crafts/*.json` — наши характеристики самолётов (значения из
  `gdata.dat`, ключи snake_case).

## Соглашения движка (правая система, как в OpenGL)

- X вправо, **Y вверх, нос смотрит в −Z**. Курс 0° = −Z, положительный курс —
  поворот вправо. Лицевые треугольники — против часовой стрелки, `GL_CULL_FACE`
  включён.
- Ориентация: `yaw(−heading, Y) · pitch(pitch, X) · roll(bank, Z)` — знак у yaw
  минус именно из-за правой системы (см. `FlightState::orientation`, тест
  `forward_matches_orientation_quaternion`).
- Симуляция — фиксированный шаг 120 Гц (`FixedStep`), рендер — переменный.
- Песочница: свободная камера. ПКМ зажата — обзор мышью, WASD — движение,
  E/Space — вверх, Q/C — вниз, Shift ×8, Ctrl ×1/8, колесо — базовая скорость,
  R — вернуть камеру к ряду самолётов, 1…4 — состояния `im0`…`im3` у всех
  машин, Esc — выход.
- Ландшафт: отсчёт `(i, j)` → `(64·i, 0.2·h, −64·j)`. Геометрия
  процедурная (`gl_VertexID`, текстуры `R16I`/`R8UI`). LOD — квадродерево в
  духе CDLOD (`TerrainRenderer`): узел 16×16 квадов с шагом `2^k` отсчётов,
  шаг `S` рисуется на дальности `(L·S/2, L·S]`, `L = lodDistance = 4000 м`.
  Вершины, которых нет у шага `2S`, в последних `1 − morphStart` дальности
  плавно уезжают на поверхность шага `2S` (`terrain.vert`, `coarseHeight`),
  поэтому переключение уровня ничего не двигает, а узлы разных шагов
  стыкуются без сшивания. Условие отсутствия щелей — в комментарии к
  `morphStart`; нарушать его (крупнее узел, меньше `L`) нельзя.
- Глубина логарифмическая, пишется **только во фрагментном шейдере**
  (`gl_FragDepth` из `vLogZ`, `uLogDepth = 2 / log2(far + 1)`); `gl_Position.z`
  не трогать — иначе треугольники через ближнюю плоскость режутся неверно
  (дыры в земле у камеры). Все шейдеры, пишущие глубину, обязаны это делать.
- Туман высотный: `σ(y) = σ0·exp(−y/H)`, `σ0 = 0.000085`, `H = 2500 м`,
  интеграл вдоль луча аналитический (`ech::heightFogTransmittance`, копия в
  `lit.frag`/`terrain.frag`/`water.frag`).

## Данные оригинала

Подробности — в `docs/specs/`. Здесь только то, что легко сломать по пути.

- Оси конвертировать только через `ech::meshToEngine` / `ech::d3dToEngine`
  (`src/core/include/echelon/math/frame.hpp`). Экспортёр повторяет их функциями
  `to_engine` / `d3d_to_engine` и не должен расходиться. Движок на лету ничего
  не переворачивает. Отвергнутые варианты (перестановка индексов, `to_engine`
  для позиций узлов) — в `docs/specs/containers.md`.
- Экспорт: `python tools\legacy_export.py [--craft Human_BF1|all --lod 0 --damage N]`.
  Раскладка `model.json` и EMSH v2 — `docs/specs/export.md`.
- Ландшафт: `python tools\terrain_export.py [--terrain Continent]` →
  `assets/legacy/terrain/<name>.eterr` (zlib, v2) + `.terrain.json`. Форматы `.sq`/`.vb`,
  слоты текстур `default#terrmtl` и `.eterr` — `docs/specs/terrain.md`.
- Свет считается в линейном RGB, кадровый буфер — sRGB. Не отключать
  `GL_FRAMEBUFFER_SRGB` из-за того, что WGL сообщает `GL_LINEAR`: на этой машине
  кодирование при этом работает, условная проверка давала тёмный кадр.
  Остальное — `docs/specs/rendering.md`.
- Недочитанное и баги сборки моделей — `docs/specs/open.md`.

## Отладка

- `echelon.exe [--terrain <name>] [--damage N] [--show-hidden]
  [--cam <x> <y> <z> <yaw> <pitch>] --screenshot <file.png> [--frames N]`
  — детерминированный кадр (ввод камеры игнорируется) и выход. `--cam` —
  стартовая поза камеры (метры движка, yaw 0 = взгляд в −Z, 180 — в +Z);
  без неё камера смотрит на начало ряда самолётов. Весь Continent сверху
  (центр карты, 400 км, почти в надир): `--cam 172000 400000 -192480 0 -89`.
  Обзор одного района: `--cam 40000 3500 -20000 45 -15`. Узлы ландшафта по
  дальности не отбрасываются — только frustum и LOD. В логе раз в 2 с — fps, позиция камеры,
  высота над землёй, число узлов и треугольников ландшафта. Проверка на
  «хлопки» LOD: серия `--screenshot --frames 5` с шагом камеры 2 м через порог
  переключения узла под камерой (`maxY + 300 + lodDistance`) и средняя
  разность соседних кадров stdlib-скриптом в `tools/temp/` — всплеска быть
  не должно (у старого блочного LOD он был ×4).
  Кадры проверки класть в `build-x64-msvc17/screenshots/` (дерево `build-*/`
  уже в `.gitignore`), не в `$env:TEMP` и не рядом с `echelon.exe`.
- Проверку данных (обход треугольников против нормалей, содержимое записей)
  удобнее делать stdlib-скриптами поверх `Container` из экспортёра.
