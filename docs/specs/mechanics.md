# Системы и чем они являются

Нужно, чтобы при планировании не путать три разные вещи:

- **данные** — числа и ассеты, которые имеет смысл прочитать и перенести;
- **поведение** — код оригинала, которого у нас нет; его всё равно писать;
- **оболочка** — меню, ролики, настройки. На симуляцию не влияют.

Мультиплеер в таблицу не входит. Какие DLL это реализуют и какие имена
функций из них вообще читаются — в [modules.md](modules.md).

| Система | Где лежит | Что это | Комментарий |
| --- | --- | --- | --- |
| Корпус самолёта, LOD, повреждения `Im` | `mesh.dat`, `objects.dat` | данные, уже читаем | Вельяне — тот же меш под именами `Img`/`Lod` |
| Лётная модель | кривые в `gdata.dat` | данные + поведение | Кривые переносятся. Интегратор в ремейке уже свой |
| Оружие, ракеты, плазма, радар | `Gun`, `Rocket`, `Missile`, `Plasma`, `Radar` в `gdata.dat`; точки подвески в хвосте `objects.dat` | данные, поля не выписаны | Поведение стрельбы писать заново. Точки `Duza*` / `ROCKETA` ещё не разобраны |
| Взрывы и обломки | `Expl*`, `Debris`, во второй игре `DetachedPart` | данные (имена и, вероятно, параметры) | Физику обломков пользователь отложил |
| Анимация | `Animation` / `AnimationPackage` только во второй игре, внутри `gdata.dat` | данные, формат полей неизвестен | Отдельных файлов скелета нет |
| Струя сопла, дымы | `particles.dat`, `Flares.dat` | данные | Рендер частиц писать заново. Профили `DXMC` — состояния DX7, в OpenGL не переносятся |
| Ландшафт | `Scenes/*.sq` `.vb` `.hd`, слоты в `rdata.dat` | данные, высоты, диагонали, текстуры и вода читаются | Continent уже в песочнице (`tools/terrain_export.py`). `.bx` и карты освещения не разобраны |
| Объекты на земле | `objects2.dat`, `Scenes/*.ros` | данные | Здания и россыпь деревьев |
| Погода, небо, вода, ночное видение | `rdata.dat`, `VisualConfigs.dat` | данные | Набор слоёв по времени суток, не один шейдер |
| Миссии | `*.cmp` или пара `.gsl`+`.gsd`, схема команд в `AICommands.dsc` | данные | Исполнитель команд — нативный `Standart.ai` / `StdLogic.ai`. Скрипт переносить как данные, интерпретатор писать |
| ИИ бота | пороги в `AiData.dat`, код в `.ai` | пороги — данные, код — поведение | Имеет смысл снять числа `FireDistance`, `Skill`. Логику бота писать по этим числам, не дизассемблировать DLL без отдельного решения |
| Звук и голос | `DSFX`, `Menu.wav`, индекс `GSND` | данные | WAV меню читается сразу. Банки голоса ещё не декодируются |
| Ролики | WMV / AVI | данные | Готовые файлы, своего формата нет |
| HUD и камеры | команды `cm_*`, `hud_*`, имена камер в `Configs.cfg` | поведение | Список режимов известен (кабина, бой, свободная, орбита, TV, тактическая). Математики камер в файлах нет |
| Клавиши | `Configs.cfg`, `common.dlc` | данные | Имеет смысл когда-нибудь прочитать как раскладку по умолчанию. Геймпад пользователь откладывал |
| Меню, ангар, кампания-оболочка | `pictures.dat`, Python `Menu15`, `Menu.dat` | оболочка | Список экранов полезен как чеклист. Виджеты DX7 и Python 2.2 писать незачем |
| Коллизия частей | `boxes.dat` | данные | Сфера и плоскости. Не читается |

## Порядок, который не требует новых решений

Он следует только из того, что уже опознано, и не заменяет план работ.

1. Дочитать то, без чего нельзя стрелять и ставить самолёт на землю: точки
   подвески, поля `Gun`/`Rocket` в `gdata.dat`. Высоты земли уже есть
   (`Heightfield::heightAt`).
2. Миссии трогать после этого: сначала схема одной команды из `AICommands.dsc`
   (как у неё устроены поля в `.gsl`), не все кампании сразу.
3. Голос и погоду можно отложить: файлы найдены, геймплей от них не начинается.
4. `.ai`, `DXMC` и Python-меню не дизассемблировать, пока не понадобится
   конкретное число, которого нет в текстовых базах.
