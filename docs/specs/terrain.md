# Ландшафт

Каталог `Data/Scenes/`. Первая игра: `Continent`, `NetArena`. Вторая добавляет
`Arctic`, `netislands`, `rockyisland`, `polygon1`, `PPK_race`, `tahiti`,
`scorpions`, `dq_islands`, `dq_storm` и обзорные BMP.

Один уровень — набор файлов с общим именем и разными расширениями. Код чтения
в оригинале — `Terrain.dll` (см. [modules.md](modules.md)); адресация и
интерполяция ниже сверены с её дизассемблером (`GroundLevel`, `WaterLevel`,
функции `10001070` и `10001130`). Разбор самой DLL — [terrain_dll.md](terrain_dll.md).
Экспорт — `tools/terrain_export.py`,
рендер в песочнице — `src/app/render/terrain_renderer.cpp`.

## Сетка — проверено

`Name.hd` начинается с двух `u32`: число чанков по X и по Y. Чанк — 128×128
отсчётов высоты, отсчёт — 64 м.

| Карта | Чанки | Отсчётов | Размер |
| --- | --- | --- | --- |
| NetArena | 6×6 | 768×768 | 49×49 км |
| Continent | 42×47 | 5376×6016 | 344×385 км |
| Arctic | 12×16 | 1536×2048 | |
| netislands, rockyisland, polygon1, PPK_race | 4×4 | 512×512 | |
| tahiti | 2×2 | 256×256 | |
| dq_islands, dq_storm, scorpions | 1×1 | 128×128 | |

Отсчёт `(i, j)`: `i` — столбец (D3D X, первый аргумент `GroundLevel`), `j` —
строка (D3D Z). В нашей системе это точка `(64·i, 0.2·h, −64·j)`.

## `.hd` — частично

- `u32 chunksX, chunksY`.
- С байта 8: 19 записей `{f32 x, y, z; u32 1}` — направления на солнце,
  по одному на карту освещения `.l00`…`.l18` (у NetArena их 10).
- С байта 520: `u32 30` и 30 `int` со значениями 1…7
  (`4,4,4,4,3,3,3,1,1,1,1,1,5,6,7,…`). Вероятно, это класс поверхности для
  каждого слоя текстуры (ср. 3-битный класс в `.sq`), не проверено.

## `.sq` — высоты, проверено

Запись на отсчёт: `{i16 height; u16 flags}`. Высота в метрах —
`height · 0.2` (Continent: −594…3458 м).

Раскладка плиточная: плитки 32×32 отсчёта, внутри плитки построчно, плитки
построчно по карте (у Continent 168×188 плиток). Индекс отсчёта:

```
k = ((i >> 5) + (j >> 5) · tilesX) · 1024 + (j & 31) · 32 + (i & 31)
```

Флаги:

- бит 15 — диагональ квада `(i, j)…(i+1, j+1)`: если бит стоит, квад разбит
  по диагонали 00–11, иначе по 10–01. `GroundLevel` (доли `fx`, `fz` по `i`
  и `j`) при стоящем бите: `fx ≥ fz` → `h00 + (h10−h00)·fx + (h11−h10)·fz`,
  иначе `h00 + (h01−h00)·fz + (h11−h01)·fx`. Реализация и тест —
  `Heightfield::heightAt`, `tests/heightfield_test.cpp`;
- биты 0–2 — число 0…7, похоже на класс поверхности (не проверено);
- бит 11 — у ~36% отсчётов, смысл неизвестен.

## `.vb` — текстуры и вода, проверено

Запись 16 байт на ячейку 4×4 отсчёта (256 м). Раскладка плиточная, плитки
16×16 записей (`10001130`: `((a & ~15) + (b & ~15) · N) · 16 + (b & 15) · 16 + (a & 15)`).

| Байты | Поле |
| --- | --- |
| 0–1 | `u16` = 3 (0 у немногих записей) |
| 2–3 | `i16` уровень воды · 0.2 м; 0 — море, −2500 — воды нет, 300 — горные озёра |
| 4–5 | `i16`, почти всегда равно уровню воды |
| 6–7 | 0 |
| 8 | слой текстуры A |
| 9 | слой текстуры B, `0xFF` — нет |
| 10–11 | `u16` = 101 |
| 12–15 | `u32` маска, 25 бит |

Маска — по биту на каждую из 5×5 угловых вершин ячейки, бит `vy·5 + vx`:
стоит → у вершины слой B, иначе A. Проверено согласованностью на общих
рёбрах соседних ячеек: 152320 из 152320 вершин совпадают. Другие гипотезы
(бит → A, порядок `vx·5 + vy`) дают 34–53%.

`WaterLevel` читает уровень этой сетки билинейно с шагом 1/256 — значения
относятся к углам ячеек.

## Слои текстур — проверено

`rdata.dat`, запись `default#terrmtl` (564 байта): хеши имён из `textures.dat`
и `materials.dat`.

- байт 8 — текстура `detail`, материал `GroundDynamic`;
- байт 28 — `env` с материалом `Water`;
- с байта 52 — 32 слота `{u32 textureHash, u32 materialHash, u32 −1, u32 0}`.

Слоты: 0 `terr_water1`, 1–4 `terr_forest1/2/3/5`, 5–10 `terr_lug1…6`,
11–13 `terr_rocks1/5/6`, 14–15 `terr_snow3/4`, 16 `terr_ruda` (DXT3),
17–19 `terr_mount3/1/2`, 20 `terr_rocks4`, 21–22 `terr_snow1/2`,
23–24 `terr_sand1/2`, 25 `CITYGRND`, 26 — пусто, 27 `BASEGRND`
(аэродромы), 28 — пусто, 29–31 `terr_field4`. Все текстуры 256×256.
На Continent встречаются индексы 0…29.

Масштаб повторения текстур в оригинале не найден; песочница кладёт одну
текстуру на 512 м (`TerrainRenderer::tilePeriod`) и добавляет `detail`
вблизи.

`ContMap<X><Y>` в `textures.dat` — тактическая карта Continent (плитки
256×256 по 512×512 отсчётов, каждую при склейке надо отразить по V) с
нарисованной сеткой и подписями. Для раскраски земли она не нужна.

## Остальные слои — не разобрано

| Расширение | Размер | Что видно |
| --- | --- | --- |
| `.bx` | 256 байт на плитку 32×32 | Вероятно, min/max по блокам для трассировки лучей |
| `.l00`…`.l18` | 256 байт на плитку | Карты освещения под направления солнца из `.hd` |
| `.bmp` | разный | Обычный BMP, обзорная карта. Есть у второй игры |
| `.bmq` | разный | Тоже начинается с `BM`. Меньше парного `.bmp` |
| `.ros` | единицы килобайт | `EVG1`. Строки `treesa`, `treesb`, `Density`, `Dispersion`, `ObjectName` — россыпь объектов по карте |

## Наш формат `.eterr`

`tools/terrain_export.py [--terrain Continent]` →
`assets/legacy/terrain/<name>.eterr`, `<name>.terrain.json` (слоты → PNG,
`detail`, средний цвет `detail`, вода) и PNG текстур в
`assets/legacy/textures/`.

На диске — **v2**: тот же файл v1, сжатый zlib (уровень 9, обёртка RFC 1950,
как `zlib.compress` в Python). Распаковывает `Heightfield::parse` через miniz.

```
'ETER', u32 version=2, u32 uncompressedSize, zlib(файл v1)
```

v1, уже распакованный:

```
'ETER', u32 version=1, u32 width, u32 height, u32 cellsX, u32 cellsY,
f32 sampleSpacing (64), f32 heightScale (0.2)
i16 height[height][width]      построчно, строка j = D3D Z
u8  flags[height][width]       старший байт флагов .sq (бит 7 — диагональ)
u8  cell[cellsY][cellsX][16]   записи .vb без изменений, построчно
```

Читает `Heightfield::parse` (`src/core/.../terrain/heightfield.hpp`). v1 без
обёртки тоже принимается.

## Что из этого следует

Ландшафт — регулярная сетка высот, а не произвольная полигональная сцена.
Объекты (деревья, здания) лежат отдельно: деревья в `.ros`, здания по именам
из `objects2.dat`. Небо — в `rdata.dat` (см. [presentation.md](presentation.md)).
Правило осей для координат объектов миссий ещё нужно подтвердить; для самой
сетки оно выше.
