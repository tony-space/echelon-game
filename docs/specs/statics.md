# Статика: здания, ангары, базы, мосты

Как вторая игра («Шторм: Солдаты Неба») описывает неподвижные объекты и куда
их ставит на карту. На диске только она: `legacy/Echelon Wind Warriors/`.
Подсчёты `Static` ×261 и `Layout` ×340 в [gdata.md](gdata.md) сняты с первой
игры; ниже — эта установка.

Текст типов лежит в `Data/gdata.dat` (контейнер `DATA`, см.
[containers.md](containers.md)). Расстановка по Continent — в миссии
`Data/Wind Warriors.gsd` (`EVG1`, см. [evg.md](evg.md)), не в самом `gdata` и
не в `Scenes/*.ros`.

Хеш имени, которым и контейнер, и миссия ссылаются на строку: `~crc32` от
байтов cp1251 **без** завершающего NUL (`zlib.crc32`, затем побитовое «не»,
младшие 32 бита). **Проверено** на всех 764 именах `objects2.dat` и на типе
каждой записи `StdStatic` (см. ниже).

## Куда разложен текст

`gdata.dat` — не один текст, а 30 записей. К статике относятся:

| Запись | Заголовок | Что внутри |
| --- | --- | --- |
| `Statics` | `[STORM STATICS DATA FILE V1.1]` | 438 `Static(...)` |
| `Roads` | `[STORM ROAD DATA FILE V1.0]` | 14 `Road(...)`, из них мосты |
| `Radars` | `[STORM RADAR DATA FILE V1.1]` | 17 `Radar(...)` |
| `Carriers` | `[STORM CARRIERS DATA FILE V1.0]` | 9 `SeaCarrier`, 4 `AirCarrier` |
| `Turrets` | `[STORM TURRET DATA FILE V1.1]` | 37 `Turret(...)` — то, что `Layout` сажает в слоты |
| `UnitDatasTable` | бинарная | 22 кода `UnitData` (`Bld`, `BigBld`, …) |

Синтаксис общий с бортом: `Имя("...") { ... }`, присваивание `Ключ = значение`,
`;` — комментарий до конца строки, вложенные вызовы со своими скобками.
Строки в кавычках, cp1251.

`Layout` во второй игре — **не** отдельный объект карты и не список зданий
с относительными позами. Это именованный набор слотов внутри `Static`
(334 вызова `Layout(` в записи `Statics`, ещё 49 в `Carriers` и 32 в `Crafts`).
`Subobj(` в статике нет: 34 вызова `Subobj` сидят в `Vehicles`. В `Statics`
есть только поле `SubobjDebris` (имя обломка).

## `Static` — тип объекта

438 определений. Игровой класс — строка `UnitData`, индекс в
`UnitDatasTable`:

| Код | Сколько `Static` | Смысл по составу |
| --- | --- | --- |
| `Bld` | 138 | дом, стена, ангар, бункер, башня |
| `BigBld` | 254 | крупная база, завод, кусок города |
| `HTG` `MTG` `LTG` | 5+6+4 | наземная турель (тяжёлая / средняя / лёгкая) |
| `HTA` `MTA` `LTA` | 4+5+5 | зенитная турель |
| `HTR` | 2 | ракетная турель |
| `+` | 12 | разрушенный остов (`Small ShaBoR Destroyed`, …) |
| нет ключа | 3 | `Vulkan`, `NullT Beam`, вспышка |

Поля самого `Static` (не у каждой записи все):

| Поле | Пример | Смысл |
| --- | --- | --- |
| `Side` | `HUMANS`, `NEUTRAL` | сторона |
| `UnitData` | `"Bld"` | код из таблицы выше |
| `DeltaY` | `11.88` | вертикальная поправка типа, метры. **Гипотеза:** сдвиг меша относительно точки постановки; у экземпляра на карте своя поправка (см. ниже), это не она |
| `Animation` | `"StaticLightsHuman"` | имя клипа из записи `Animations` |
| `Avoidable` | `1` | объезжать (башни, куски New Avalon) |
| `OtherSideData` | `"H2V Military Hangar 150m"` | тот же объект другой стороны; имя тоже есть среди `Static` |
| `Position` | `(x, y, z, a)` | только у 54 `New Avalon *`. Это уже координаты мира, не крепление детали. См. ниже |
| `Layout(SLOTS, "вариант")` | | набор слотов, не поза |
| `Root("Main")` | | корпус |

### Корпус, части, броня

```
Root("Main") {
  Armor = 20000       ; (87    34    155)
  FileName        = "dom_mil"
  Debris          = "Static_hull_debris"
  DetachedDebris  = "Big_Static_part_debris"
  SubobjDebris    = "Static_subobj_debris"
  Part("AngA") {
    Armor = 10000       ; (80     44    18)
    ObjectName      = "AngA"
    DetachedDebris  = "..."
    SubobjDebris    = "..."
  }
}
```

`FileName` — имя меша. **Проверено:** оно есть в `objects2.dat`, а в
`mesh.dat` от него начинаются записи LOD/повреждений
(`dom_mil_Im2_Ld0`, `angar_sklad_150m_AngA_...`, `bunker1_towerA_...`,
`fh01_Im2_Ld0`, `wall_war_Im0_Ld0`, `hs_base1_TOWER_...`). Как у борта:
голое имя — корпус, дальше `_` + `ObjectName` части. Сами вершины здесь не
разбирались.

`ObjectName` — имя части внутри этого меша. У `Part` статики **нет** поля
`Position` (**проверено:** в `Statics` ни одного трёхкомпонентного
`Position`). Сборка частей — узлы `objects2` / меш, тем же способом, что
узлы самолёта в `objects.dat`.

`Armor` — число прочности. Комментарий `(a b c)` сразу за ним —
габарит. **Проверено** на одном совпадении: `Military Hangar 150m` имеет
`(44 18 150)` и `(44 18 70)`, и 150 — это метры из имени. **Гипотеза:** все
три числа — размеры бокса в метрах (ширина, высота, длина); вторая строка
комментария — второй бокс (целый / повреждённый). Отдельного поля health нет,
прочность — это `Armor`.

`DetachedPart("hulle")` — то же дерево, но деталь отрывается; внутри только
`Armor` и `ObjectName`. Так собраны куски New Avalon.

### Дом

`Military Bld 0`, меш `dom_mil`, `UnitData = "Bld"`, `DeltaY = 11.88`,
`Side = HUMANS`, `Animation = "StaticLightsHuman"`, броня корпуса 20000,
габарит `(87 34 155)`. Частей нет.

Обычные дома города в миссии называются `Home 01`…`Home 10`, меш `fh01` у
`Home 01`.

### Ангар

Два слоя. Здание — `Static`. Внутри корпуса бывает вызов `Hangar`, это уже
логика посадки, не второй меш.

`Military Hangar 150m` — простое здание: `FileName = "angar_sklad_150m"`,
`DeltaY = 0.95`, одна часть `AngA`. Слотов турелей нет.

`Craft Hangar`, меш `gravang_sm`, `DeltaY = 0.83`:

```
Hangar("Bunker") {
  Animation = "Hangar"
  Critical
  Detached
  Armor = 73951       ; (84     41    128)
  ObjectName      = "Bunker"
  Door            = "door"
  BaseSlot        = "Appear"
  BfTakeoffSlot   = "BF_HVY"
  BfTouchdownSlot = "BF_HVY"
  BfTakeoffAngle  = 10
  BfTouchdownAngle= 10
  BfTakeoffTime   = 1
  Sound = "HangarDoor"
}
```

Таких вложенных `Hangar` в `Statics` — 23 (ещё 13 у авианосцев).
`Bf*` / `Int*` — слоты взлёта и посадки боевого поля и перехватчика,
`VehicleDepartSlot` / `VehicleArriveSlot` — для наземной техники.
Углы `BfTakeoffAngle = 10` выглядят как градусы; **гипотеза**, сверки
с камерой нет.

### База одним мешем и слоты турелей

`Human Base 1`, `UnitData = "BigBld"`, меш `hs_base1`. Несколько
`Layout` — это варианты вооружения одного и того же меша, не пачка зданий:

```
Layout(SLOTS,"Turrets & Radar 30000m") {
  "aahtrs1 (-110, 120)" = "HS AAC Heavy Plasma Turret"
  "hradar4"             = "HS Radar 30000m"
}
```

Ключ — слот. Значение — имя из `Turrets` или `Radars` (**проверено:**
`HS Heavy Cannon Turret`, `HS Radar 15000m` и остальные значения из
разобранных `Layout` там есть). У части, к которой слот относится,
тот же ключ повторён комментарием:

```
Part("towerA") {
  ObjectName = "towerA"
  ; "htrs (-115, 130)" = ""
}
```

**Гипотеза:** строка в скобках — пределы курса орудия в градусах, а не
сдвиг в метрах. Какой из вариантов миссия выбирает, в записи экземпляра
не видно: поля `Layout1`…`Layout4` у просмотренных `StdStatic` пустые
(см. ниже).

`Bunker Heavy`, меш `bunker1`, `DeltaY = 12.59`, устроен так же:
шесть `Layout(SLOTS, ...)` на два слота `htrs`, части `towerA` / `towerb` /
`kolpakA`…`C`.

### Огневая группа, радар, носитель

`Sfg("Aerial")` вложен в корпус (11 раз в `Statics`):

```
Sfg("Aerial") {
  SfName    = "gpp_500m"
  SfRadius  = 500
  Armor = 200000       ; (75     110    76)
  ObjectName = "Aerial"
}
```

`SfRadius = 500` — метры зоны. **Гипотеза** по имени, отдельной проверки нет.

`Radar("HS Radar 10000m")` — отдельная запись `Radars`, не `Static`.
Поля: `UnitData = "rdr"`, `DeltaY`, `FileName`, `SensorRange`, `CornerSpeed`,
`Armor`, дерево `Part`. Этими именами заполняются слоты `Layout`.
Отдельный `Static("Radar Complex 1")` — уже здание комплекса.

`SeaCarrier` / `AirCarrier` — запись `Carriers`. Помимо корпуса и `Hangar`
у них ход: `MaxSpeedZ`, `MaxAccelZ`, `ASpeedX`, `AAccelX`, у воздушного
ещё `MaxSpeedY`, `PitchLimit`. Это юниты, не декор карты. Куда миссия их
ставит, этим разбором не закрыто (в `.gsd` есть поведение `StdCarrier`,
запись не читалась).

### Мост — это `Road`, не `Static`

```
Road("Human Bridge Metal") {
  Type="Bridge";
  Width=50;
  EntranceHeight=33;
  EntranceDeltaHigh=81;
  EntranceDeltaLow=10;
  EntranceObject="riverbridge200m_be";
  SectionObject ="riverbridge200m_part";
}
```

Так же `Human Railroad Bridge` (`railroadbridge600m_part`),
`Human Light Bridge`, `Human Sea Bridge`, `Human Tunnel`, `Human Spusk`.
Обычная дорога (`Highway`, `Dirty road`, …) задаёт `Width`, `Type="Road"`,
`SectionScript`, `SectionTexture`, `SectionMaterial` и не ссылается на меш.

`SectionObject` / `EntranceObject` — те же ключи меша, что `FileName`.
**Проверено:** `riverbridge200m_part` и `railroadbridge600m_part` есть в
`objects2.dat` и в `mesh.dat`. Ломаная, по которой секции стоят на карте,
в тексте `gdata` нет; в `Wind Warriors.gsd` нет и самих строк
`"Highway"` / `"riverbridge"`. Хеш `~crc32` этих имён в файле встречается
(у `"Dirty road"` тысячи раз), но первый просмотренный контекст — таблица
«хеш + порядковый id», не тройка координат. **Гипотеза:** трасса где-то в
том же `.gsd`, раскладка секции не снята.

## Где объект стоит на карте

Каноническая расстановка кампании — записи поведения `StdStatic` в
`Data/Wind Warriors.gsd`.

После отбрасывания шаблонов с типом `0xFFFFFFFF` (760 штук, координаты
`NaN`) остаётся **6148** экземпляров, все в одном участке файла
(смещения примерно 2.2…5.8 МБ), без повторов ключа
`(имя, x, z)`. Тот же тег `StdStatic\0` есть в `Training Course.gsd` и
`Instant Action.gsd`; `Deathmatch Arena.gsd` его не содержит. Дальше
посчитан только `Wind Warriors.gsd`.

Запись — 238 байт, хвост из имён полей постоянный:

```
+0    char tag[10] = "StdStatic\0"
+10   u8  0
+11   u16 различается у экземпляров     ; смысл не установлен
+13   байты 13 0f 00 00                 ; постоянны
+17   16 байт 0xFF                      ; гипотеза: пустые ссылки
+33   u32 type                          ; ~crc32(имени Static), проверено
+37   f32 x, y, z                       ; метры D3D, проверено
+49   u32 10                            ; число полей
+53   10 × { u32 value, u32 id, u32 nameOff }
+173  "Name\0Layout3\0Flags\0Angle\0Ai\0Layout2\0Layout4\0Org\0AiScript\0Layout1\0"
```

`StdStaticHangar\0` — тот же хвост, тег длиннее на 6 байт, вся запись 244
байта, `x,y,z` сдвинуты на +6. **Проверено** на одной записи: это
`Craft Hangar` в точке D3D `(180733.4, −7.1, 369359.2)`.
Рядом в файле ещё `StdStaticSfg` (8) и `StdStaticGroup` (122); их тела
не разбирались. Группа, судя по соседству тегов, короткая и стоит
вплотную к дочерним `StdStatic`. **Гипотеза.**

Поля `Name`, `Layout1`…`Layout4`, `Flags` у просмотренных тысяч записей
держат одно и то же значение-заглушку `0x189596B9`. `Angle`, `Org`, `Ai`,
`AiScript` тоже константы на всех 6148:

| Поле | Сырое значение | Как float |
| --- | --- | --- |
| `Angle` | `0x3FCFC71D` | 1.623264 |
| `Org` | `0x2AF9C65D` | ~0 |
| `Ai`, `AiScript` | `0xAF293CAF` | крошечное отрицательное |

Побайтовое сравнение двух `Home 01` различается только в `u16` по +11,
в координатах и в `id` десяти полей. Отдельного курса, тангажа и крена
на экземпляр в записи нет. **Проверено.**

Что делать с константой `Angle` — **гипотеза**. 1.623264 радиан ≈ 93.01°.
Если движок читает поле как градусы, это ≈ 1.62° и почти ноль. В `gdata`
у New Avalon четвёртое число `Position` равно 0, то есть автор базы курс
не задавал. Пока ремейк не сверит кадр с оригиналом, ставить меш как
есть, без этого угла.

### Оси

**Проверено.** `x` и `z` — метры D3D: X вправо, Z «от камеры» вглубь карты,
тот же смысл, что у отсчёта ландшафта `(i, j) → (64·i, *, 64·j)` в
[terrain.md](terrain.md). Точка попадает в клетку `(round не нужен: i = x/64, j = z/64)`.

Высота земли читается из `Continent.sq` правилом из terrain.md; диапазон
высот тем чтением выходит −594…3445 м, как в спецификации ландшафта.

`y` экземпляра — поправка к земле в метрах, не абсолютная высота.
**Проверено** на домах и ангаре: `Home 01` в `(129379, 102676)` имеет
`y = 1.1` при земле 121 м; `Military Hangar 150m` в `(98860, 361762)` имеет
`y = 0` при земле 10.4 м. Мировая высота ≈ `GroundLevel(x, z) + y`.
У стен и домов поправка обычно в пределах нескольких метров.

Исключение — 54 куска `New Avalon *`. У них `y ≈ −GroundLevel`, сумма
около нуля:

| Имя | x | y миссии | z | Земля, м | y + земля |
| --- | --- | --- | --- | --- | --- |
| New Avalon 011 | 135156.1 | −21.0 | 366371.4 | 21.0 | 0.0 |
| New Avalon 0125 | 134195.7 | −21.0 | 357748.5 | 21.0 | 0.0 |
| New Avalon 0411 | 137923.2 | −59.7 | 347724.9 | 60.0 | 0.3 |
| New Avalon 043 | 131040.0 | −240.3 | 356208.0 | 244.6 | 4.4 |

**Гипотеза:** меш куска города уже собран в абсолютной вертикали, и его
сажают в ноль по высоте. В `gdata` у тех же имён записан
`Position = (x, Y, z, 0)`, `x`/`z` совпадают с миссией с точностью до
сотых, а `Y` — нет (у 011 в базе 554 м, земля сейчас 21 м). Для постановки
брать `y` из `.gsd`.

В систему ремейка, как и прочие координаты D3D: `(x, y, z) → (x, y, −z)`.

### Что не является расстановкой зданий

`Scenes/continent.ros` — россыпь, не здания. Строки там: `treesa`…`treesj`,
`stone1`…`3`, `rstolb1`…`3`, `bf1ruins`, плюс `Density`, `Dispersion`,
`ObjectName`. Имён `Static` нет.

`Position` в `gdata` есть только у New Avalon (54 штуки, четвёртое число
всегда 0). Остальные 384 `Static` координат не несут.

## Что читать, чтобы поставить города Continent

1. Запись `Statics` из `gdata.dat`: имя, `FileName`, дерево `Part` /
   `ObjectName`, `DeltaY`, при необходимости `Layout` и `Hangar`.
2. `Wind Warriors.gsd`: каждый `StdStatic` длиной 238 байт с типом
   `~crc32(имени)` и тройкой `(x, y, z)`.
3. Меш по `FileName` из `objects2.dat` / `mesh.dat` (чужая задача).
4. Мировая точка D3D `(x, GroundLevel(x, z) + y, z)`, затем
   `d3dToEngine`. Для `New Avalon *` сумма уже около нуля — меш, скорее
   всего, надо сажать в `y = 0`, а не ещё раз на землю. Это гипотеза.
5. Курс не читать, пока не сверён кадр: в экземпляре его нет.
6. Мосты и дороги: тип и меш секции — из записи `Roads`; ломаная на карте
   ещё не разобрана.

## Открытые вопросы

- Применяет ли движок константу `Angle` (1.623) как радианы, как градусы
  или никак. Кадра сверки нет.
- Какой `Layout(SLOTS, ...)` выбирается у базы и бункера. В экземпляре
  поля `Layout1`…`Layout4` пустые.
- Ломаная `Road` / моста в `.gsd`: хеши имён есть, координат рядом с первым
  вхождением нет.
- `DeltaY` типа против `y` экземпляра: какая сумма идёт в движок, если
  заданы оба.
- Два комментария `(a b c)` у `Armor` — один бокс или два.
- Скобки в имени слота `"htrs (-115, 130)"` — пределы курса или часть
  имени узла.
- Тела `StdStaticGroup`, `StdStaticSfg` и постановка `SeaCarrier` /
  `StdCarrier`.
- Байты +11…+16 и шестнадцать `0xFF` в заголовке `StdStatic`.
